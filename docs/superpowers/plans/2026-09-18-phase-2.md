# Phase 2 工作台与权限实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 `docs/dev/Phase2.md` 定义的工作台、一级文件夹、文档元数据、编辑权限申请、平台通知、审计查询和配额读取，并通过自动化与浏览器验证。

**Architecture:** 沿用现有 pnpm monorepo、NestJS、Drizzle/PostgreSQL、Vue/Pinia 和 OpenAPI 生成链路。后端新增模块通过事务仓储完成归属、行锁、部分唯一索引、Outbox 和审计；前端只消费生成客户端。阶段 2 使用 JSONB 保存小型初始快照，不引入导入、正式画布、历史或回收站运行时。

**Tech Stack:** Node.js 24、pnpm 11、TypeScript、NestJS、Drizzle ORM、PostgreSQL、Vue 3、Element Plus、Pinia、Vitest、Playwright、OpenAPI/Hey API。

**Spec:** `docs/superpowers/specs/2026-09-18-phase-2-design.md`

## Global Constraints

- 保持阶段 1 认证、安全、OpenAPI、数据库迁移、Compose 和测试能力兼容。
- 不实现阶段 3～6 的 XMind 导入、正式画布编辑、编辑锁、历史、搜索、回收站和生产上线能力。
- 所有 workspace、folder、document、membership ID 都由服务端重新校验归属。
- Reader、Editor、Admin 的限制由服务端守卫执行，前端隐藏按钮不能代替鉴权。
- 名称规范化函数只能有一个实现，并有单元测试。
- 数量、唯一性和状态转换必须由数据库约束或行级锁支撑。
- 游标必须包含排序值和唯一 ID；不得使用裸 offset 作为正式分页。
- 通知业务事务写入持久化 Outbox，不能使用提交后的内存回调。
- 不读取、输出或提交真实 `.env`，不自动执行 Git commit。
- 保留用户现有的 `target.md` 删除状态和未跟踪开发文档。
