# Shared Mind Map Phase 0-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the verified phase 0 technical decisions and a runnable phase 1 platform foundation with local authentication, account administration, generated API client, independent XMind worker, and complete local infrastructure.

**Architecture:** A pnpm TypeScript monorepo keeps the Vue web app, NestJS API, Node worker, database layer, canonical document model, XMind boundary, and generated API client in explicit ownership boundaries. PostgreSQL and MinIO remain persistent sources of truth, Redis owns only sessions/coordination/rate limits, and every user-facing contract originates in OpenAPI.

**Tech Stack:** Node.js 24, pnpm 11, TypeScript, Vue 3, Vite, Element Plus, Pinia, Vue Router, NestJS, Drizzle ORM, PostgreSQL 17, Redis 7, MinIO, BullMQ, Zod, Argon2id, Vitest, Supertest, Testcontainers, Playwright, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-16-phase-0-1-design.md`

## Global Constraints

- Implement only phases 0-1. Do not add phase 2-6 production features or fake production endpoints.
- Use the existing `apps/`, `packages/`, `tests/`, `scripts/`, `infra/`, and `docs/` boundaries; do not create generic `utils`, `contracts`, or `config` packages.
- Preserve dependency flow: `web -> api-client + document-model`, `api -> database + document-model`, `worker -> database + document-model + xmind`.
- Use Node.js 24 and pin the installed pnpm 11 release in `packageManager`; do not add Nx or Turborepo.
- Use UUIDv7 throughout the phase 1 database and API; do not mix in ULID.
- Cloud documents and persisted APIs may not expose a canvas library's node model.
- XMind decompression, parsing, and conversion run only in the independent worker or package tests, never on the API event loop.
- PostgreSQL and MinIO are persistent facts; Redis must not be the only copy of business data.
- Passwords use Argon2id. Never log passwords, hashes, temporary passwords, cookies, CSRF values, session tokens, secrets, document bodies, or image bytes.
- Authentication uses an HttpOnly cookie and a server-side Redis session. The browser must not persist credentials.
- Every restricted behavior is enforced on the server; hidden frontend controls are not authorization.
- Real `.env` files must not be read, printed, or committed. `.env.example` contains local-only values or obvious placeholders.
- Apply red-green-refactor for production behavior. Record the failing command/output before implementation and passing command/output after it.
- Do not modify the four baseline documents unless resolving a confirmed contradiction.
- Do not run `git commit`. `target.md` explicitly withholds commit permission; task checkpoints use SDD reports and before/after filesystem snapshots.
- Generated artifacts must have deterministic regeneration and a non-Git drift check that works with an intentionally uncommitted worktree.
- Every task finishes with focused tests, workspace format/lint/typecheck where applicable, and a task report before review.
