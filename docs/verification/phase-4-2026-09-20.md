# Phase 4 验证报告

日期：2026-09-20
环境：Linux WSL2，AMD Ryzen 9 7940H（16 线程），内存 7.91 GiB，Node `v24.16.0`，pnpm `11.5.0`，Playwright `1.63.0`，Chromium `153.0.8010.12`。

## 已实现范围

- 正式文档页 `/workspace/documents/:documentId`；Reader、移动端、未持锁成员只读，当前持锁桌面会话可编辑。
- `CloudDocumentV1` 与 mind-elixir 的适配边界、版本元数据、兼容性提示和标准快照保存。
- Redis 单编辑锁的获取、心跳、释放、强制释放、失锁只读切换和公开锁状态广播。
- 自动保存串行队列、幂等保存、版本冲突保护、用户/工作区/文档隔离草稿、离开页面和关闭窗口保护、草稿 JSON/XMind 导出入口。
- PNG/JPEG/WebP 文件选择、粘贴、拖放、5 MiB 客户端边界及服务端真实媒体校验；快照只保存服务端返回的资产 ID。
- Socket.IO 文档房间、100 人上限、presence、提交后广播、旧版本过滤和版本跳跃 REST 回补。
- 强制释放、权限撤销、服务重启/重新认证、网络/版本冲突等故障路径均保留本机脏草稿。

## 恢复路径证据

`tests/e2e/phase4-recovery.spec.ts` 共 5 个测试通过，覆盖：

1. API 服务重启后等待就绪，必要时重新认证，再通过 REST 重新加载原文档；稳定阶段无意外控制台错误。
2. 强制释放后的旧锁保存返回 `423 LOCK_LOST`。
3. 浏览器存在图片脏草稿时被强制释放，页面切换只读并保留“复制草稿 JSON”。
4. 编辑权限撤销后保存返回权限错误，页面切换只读并保留脏草稿。
5. 新版本提交后旧 `baseVersion` 保存返回 `409 DOCUMENT_VERSION_CONFLICT`。

另外，双浏览器锁竞争测试通过：第一个桌面会话获得编辑锁，第二个会话保持只读。实时客户端单元测试覆盖旧版本过滤、版本跳跃 REST 回补、重连重新加入房间且不自动重获锁。
