## 1. 目标与非目标

### 1.1 目标

- 在 TestHub 左侧导航新增「接口测试」，管理员可查看用例集并一键执行。
- **用例代码直接维护在本仓库** `api-tests/`，不再依赖 `api-test` 仓库。
- 新增回归用例 = 在 `api-tests/testcases/<suite>/` 加一个 pytest 文件；重新部署后即可一键执行。
- 执行结果落库：通过/失败/跳过数、耗时、失败堆栈、请求与响应摘要、失败时的 curl。
- 平台不重写用例，直接跑 pytest。

### 1.2 非目标

- 不替代 `api-test` 的全量回归；两套代码此后各自演进。
- 不提供在线编辑 Python 代码、动态安装依赖。
- 首版不做定时任务、失败自动告警、跨轮次趋势图。
- 首版不开放给 reader/editor，仅管理员可见可执行。

## 2. 总体架构

```text
api-tests/                     ← 本仓库，唯一用例来源
  ├─ conftest.py / pytest.ini
  ├─ config/ / common/
  ├─ testcases/
  │    ├─ smoke/               ← suite: 核心冒烟
  │    ├─ checkout/            ← suite: Checkout
  │    └─ ...
  └─ harness/
       ├─ pytest_platform.py   # NDJSON 事件、捕获、白名单、超时
       └─ requirements.txt

浏览器
  │ POST /api/v1/api-tests/runs   GET /runs/:id（1s 轮询）
  ▼
API (NestJS)
  │ 校验 → 写 api_test_runs + api_test_run_items
  │ BullMQ: api-test-run
  ▼
Redis ──────────────► Worker (Node 24)
                        │ 取 suite 目录 + 环境 base URL
                        │ spawn: python -m pytest testcases/<suite>
                        │ 读 fd3 NDJSON → 增量写 run_item
                        │ 超时/取消 → 杀进程组
                        ▼
                     PostgreSQL
```

关键点：

- **用例是仓库代码**，跟着 Worker 镜像一起部署。
- **suite = 目录**，目录里新增文件自动纳入，不需要登记 node id。
- **node id 只在执行结果里出现**，用于「重跑失败项」，不需要人工维护。
- 平台不预存用例清单；需要数量时由 Worker 跑一次 `--collect-only`（P1 做缓存）。

import pytest
from common.assertions import assert_status, assert_code


class TestGetProductRecommend:
    @pytest.mark.parametrize("params, expected_status, expected_code", [
        ({"limit": 10}, 200, 0),
        ({"limit": 0}, 400, 1001),

    def test_recommend(self, user_client, params, expected_status, expected_code):

        assert_status(resp, expected_status)
        assert_code(resp, expected_code)

## 4. pytest 平台插件

`api-tests/harness/pytest_platform.py`，通过 `-p harness.pytest_platform` 加载。

### 4.1 事件

写 NDJSON 到文件描述符 3（Worker 以 `stdio: ["ignore","pipe","pipe","pipe"]` 启动）。fd3 不可用时退回 stdout，带固定前缀。

| 事件 | 内容 |
|---|---|
| `session_start` | pid、pytest 版本、开始时间 |
| `collection_finish` | 本次收集到的用例总数 |
| `test_start` | node id、名称、序号 |
| `test_finish` | node id、outcome、duration_ms、失败摘要、捕获的 HTTP 交互 |
| `session_finish` | 汇总计数、退出码、总耗时 |

### 4.2 选例

- 正常执行：Worker 直接传 suite 目录，pytest 跑目录下全部用例，插件不做筛选。
- 重跑失败项（P1）：Worker 传上一轮失败用例的 node id 数组，插件通过 `pytest_collection_modifyitems` 只保留这些项。
- 名单中的 node id 收集不到时整轮报 `API_TEST_SELECTION_INVALID`，不静默少跑。

### 4.3 请求与响应捕获

- `pytest_configure` 包装 `common.http_client.HttpClient.request`：
  - 记录 method、url、request headers/body、status、response headers/body；
  - 每个用例单独缓冲，`pytest_runtest_setup` 时清空；
  - 默认 `API_TEST_CAPTURE=failures`：只保留失败用例的完整响应；成功用例只保留 method/url/status/耗时；
  - `all` 保留全部；`none` 全不保留；
  - 请求体 8 KiB、响应体 256 KiB 截断，标记 `truncated`。
- 生成 curl 字符串，敏感头先脱敏再拼。
- 未显式传 `timeout` 的请求补 `timeout=10`。

### 4.4 出站白名单

- 插件读取 `API_TEST_ALLOWED_HOSTS`，请求前校验目标主机；不在白名单直接抛错，该用例失败。
- 拒绝私网地址：`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`::1`、`fc00::/7`。
- `allow_redirects=False`，3xx 交给断言处理。

### 4.5 超时

- `pytest-timeout` 加入 `requirements.txt`，Worker 传 `--timeout=60 --timeout-method=thread`。
- 整轮超时由 Worker 控制（10 分钟），超时杀进程组。

### 4.6 outcome 映射

| pytest | 平台 |
|---|---|
| `passed` / `xpassed` | `passed` |
| `failed` | `failed` |
| `skipped` / `xfailed` | `skipped` |
| setup/teardown 失败 | `error` |

## 6. 执行引擎

### 6.1 流程

```text
POST /runs
  ├─ 校验 suite/environment/权限
  ├─ 同一用户已有 queued/running run → 409
  ├─ 插入 run，按 suite 文件估算/不预建 items
  ├─ enqueue api-test-run { runId }
  └─ 返回 201

Worker job
  ├─ run → running
  ├─ 取环境 base_url + suite 目录 + 账号环境变量
  ├─ spawn pytest testcases/<suite> -p harness.pytest_platform
  ├─ 读 fd3 NDJSON：
  │    ├─ test_start → 建/更新 run_item
  │    ├─ test_finish → 写 outcome/duration/交互/失败摘要
  │    └─ session_finish → 汇总
  ├─ stderr/stdout 保留最后 16 KiB
  ├─ 汇总 status（全过 succeeded；有失败 failed；取消 cancelled）
  └─ finished_at
```

`run_item` 在执行过程中创建，不预建；页面轮询时按 `ordinal` 排序展示。

### 6.2 硬限制

| 项 | 值 |
|---|---|
| 单次 run 用例数 | 200（超出则该轮失败并提示拆分 suite） |
| 全局并发 | 1（队列 concurrency=1） |
| 单请求超时 | 默认 10s（插件注入） |
| 单用例超时 | 60s（pytest-timeout） |
| 整轮超时 | 10 min |
| 响应采集 | 256 KiB 截断 |
| 请求体采集 | 8 KiB 截断 |
| 结果保留 | 每 suite 最近 100 轮，或 90 天 |
| 出站域名 | 环境变量白名单 |

### 6.3 取消

- API 写 `cancel_requested = true`。
- Worker 轮询该字段；取消时向进程组发 `SIGTERM`，5 秒后 `SIGKILL`。
- 已完成结果保留；未执行的 `run_item` 状态标 `skipped`。

### 6.4 进度

- 前端每秒轮询 `GET /runs/:id`，终态停止。
- 插件每完成一条用例就吐一行，页面能看到逐条变绿/变红。

## 8. API 设计

前缀 `/api/v1`，控制器 `ApiTestsController`，`Roles("admin")`。

| 方法 | 路径 | operationId | 说明 |
|---|---|---|---|
| GET | `/api-tests/suites` | `listApiTestSuites` | 含最近一轮摘要 |
| GET | `/api-tests/environments` | `listApiTestEnvironments` | 名称/base URL/开关 |
| POST | `/api-tests/runs` | `createApiTestRuns` | 支持多个套件，按数组顺序入队，worker 单并发串行执行 |
| GET | `/api-tests/runs` | `listApiTestRuns` | 按 suite 过滤，游标分页 |
| GET | `/api-tests/runs/:runId` | `getApiTestRun` | 报告主体，轮询用 |
| POST | `/api-tests/runs/:runId/cancel` | `cancelApiTestRun` | |
| POST | `/api-tests/runs/:runId/rerun-failed` | `rerunFailedApiTestCases` | P1 |

`POST /runs` 请求：

```json
{
  "suiteIds": ["uuid", "uuid"],
  "environmentId": "uuid",
  "confirmDestructive": false
}
```

校验：

- suite `readonly=false` 时，环境必须 `allow_destructive=true` 且 `confirmDestructive=true`。
- 环境 `base_url` 主机不在 `API_TEST_ALLOWED_HOSTS`：`API_TEST_TARGET_DENIED`。
- 环境不存在或 `enabled=false`：`API_TEST_ENVIRONMENT_UNAVAILABLE`。

新增错误码：`API_TEST_SUITE_NOT_FOUND`、`API_TEST_RUN_NOT_FOUND`、`API_TEST_ENVIRONMENT_NOT_FOUND`、`API_TEST_RUN_CONFLICT`、`API_TEST_TARGET_DENIED`、`API_TEST_CONFIRM_REQUIRED`、`API_TEST_CASE_LIMIT_REACHED`、`API_TEST_ENVIRONMENT_UNAVAILABLE`、`API_TEST_SELECTION_INVALID`。

生成客户端：`pnpm api:generate`。

## 10. 安全与运维

### 10.1 进程隔离

- 子进程 env 白名单（见 5.3）。
- `cwd` 固定 `/app/api-tests`，`USER node` 运行。
- 插件 host 白名单 + 私网地址拦截。
- 新增用例要经过 code review，禁止在 `api-tests/` 引入任意下载或执行逻辑。

### 10.2 凭据

- 账号放 Worker 环境变量，不加密、不入库；`.env` 与 `deploy/.env` 保持 600。
- 前端只显示「账号已配置」。
- 日志、审计、结果脱敏。
- 审计事件：`api_test.run.started`、`api_test.run.finished`，不记录请求体。

### 10.3 数据副作用

- 默认只跑 `readonly=true` 的 suite。
- 写 suite 需要环境 `allow_destructive=true` + 二次确认。
- 测试环境数据共享，报告记录执行人。

### 10.4 权限

- 首版所有接口与菜单仅 `admin`。

### 10.5 镜像与部署

- Worker Dockerfile：

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends python3 python3-venv \
    && rm -rf /var/lib/apt/lists/*
RUN python3 -m venv /opt/api-tests-venv \
    && /opt/api-tests-venv/bin/pip install -r /app/api-tests/harness/requirements.txt
COPY --chown=node:node api-tests/ /app/api-tests/
```

- 新增/修改用例后必须重建 Worker 镜像并部署：

```bash
deploy/make-arm64-bundle.sh --only worker
# scp + deploy.sh，见 CLAUDE.md
```

- 新增 compose 变量：`AUTH_METHOD`、`AUTH_PHONE`、`AUTH_SMS_CODE`、`API_TOKEN`、`IM_USERNAME`、`IM_PASSWORD`、`API_TEST_ALLOWED_HOSTS`、`API_TEST_CAPTURE`。
- `API_BASE_URL` 由每次 run 的环境注入，不进 compose。
- 生产机出网检查：

```bash
docker compose --env-file .env exec worker node -e \
  "fetch('https://api.kitarx.com/api/v3/auth/google/deletion').then(r=>console.log(r.status)).catch(e=>{console.error(e);process.exit(1)})"
```

| 8 | 请求挂死 | 插件补 10s 超时；pytest-timeout 60s；整轮 10min |
