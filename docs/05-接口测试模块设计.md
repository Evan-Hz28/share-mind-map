# 接口测试模块设计（P0 历史摘要）

> **历史设计稿（2026-11-10 压缩）**：V0.3 全文（585 行）保存在 git `92557f8`，可用 `git show 92557f8:docs/05-接口测试模块设计.md` 查看。当前实现以 [docs/06-项目交接文档.md](06-项目交接文档.md) §10、`api-tests/harness/pytest_platform.py` 和代码为准。

版本：V0.3（2026-10-28）｜状态：P0 已实现，仅保留可追溯的决策

## 1. 仍然成立的决策

| 决策 | 理由 |
|---|---|
| 仅 Admin 可见可执行 | 用例可发起任意出站请求并写测试环境，按最小权限开放 |
| Worker 单并发 | 生产机 1.8 GiB，单个 pytest 进程约 150 MB |
| 测试账号走 Worker 环境变量，不加密、不入库 | 避免首版引入密钥管理；前端只显示“已配置” |
| 平台不重写用例，直接执行 pytest | 不复制断言逻辑，报告只消费 fd3 NDJSON 事件 |
| 不关联 XMind 文档 | 两者生命周期独立，避免双向同步 |
| 出站域名白名单 + 私网拦截，`allow_redirects=False` | 用例代码可发起任意请求，必须设边界 |
| 写 suite 需 `allow_destructive=true` + 二次确认 | 测试环境共享，默认只读 |
| 失败才存完整响应，成功只存状态码/耗时 | 控制结果体积（请求体 8 KiB、响应体 256 KiB 截断） |

## 2. 已被推翻或补齐的设计

| P0 设计 | 现状 |
|---|---|
| 用例维护在本仓库 `api-tests/testcases/`，随 Worker 镜像部署 | 改为 Worker 运行时从上游 pytest 仓库同步到 `api-test-repo` 卷；本仓库只保留 harness |
| 与 `api-test` 解耦，“两套代码各自演进” | 反向：强依赖上游仓库，运行时同步 |
| 定时任务、失败告警列为非目标 / P2 | cron 定时执行已实现（`api_test_schedules`）；失败告警仍未做 |
| 数据模型 4 张表（迁移 `0006`） | 扩展到 `0013`：批次、测试集合、用例编目、定时任务等 |
| API 6 个端点 | 约 27 个（suites / cases / runs / batches / collections / schedules / sync） |
| 结果保留 100 轮 / 90 天 | 未实现，`api_test_runs` / `api_test_run_items` 只增不减 |
| 1s 轮询，Socket.IO 实时进度为 P1 可选 | 仍为轮询，接口测试未接 Socket.IO |
