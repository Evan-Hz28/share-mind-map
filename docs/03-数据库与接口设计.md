# 共享思维导图平台数据库与接口设计

版本：V1.1  
状态：逻辑设计基线  
更新日期：2026-09-16

## 1. 设计约定

- PostgreSQL 字段使用 `snake_case`，API JSON 使用 `camelCase`。
- 主键优先 UUIDv7；若工具链不能稳定支持，则统一使用 ULID，禁止两者混用。
- 时间以 UTC `timestamptz` 保存，显示时转换为用户时区。
- 可变表统一包含 `created_at`、`updated_at`，必要时包含 `created_by`、`updated_by`。
- 文档内容使用带版本的标准 JSON Schema，节点 ID 跨版本保持稳定。
- 并发控制使用整数文档版本号，不使用时间戳代替版本号。
- 用户删除采用回收站软删除；永久删除是明确、可审计的独立流程。

## 3. 标准文档模型

最小版本化结构：

```json
{
  "schemaVersion": 1,
  "documentId": "uuid",
  "version": 42,
  "sheets": [
    {
      "id": "sheet_uuid",
      "title": "测试用例",
      "rootNodeId": "node_uuid",
      "nodes": {
        "node_uuid": {
          "id": "node_uuid",
          "parentId": null,
          "childIds": ["child_uuid"],
          "title": "功能模块",
          "priority": "P0",
          "notes": { "format": "plain", "text": "" },
          "labels": ["冒烟"],
          "icons": [],
          "style": {
            "textColor": "#1f2329",
            "backgroundColor": "#ffffff",
            "fontFamily": "Arial",
            "fontSize": 14,
            "fontWeight": 400
          },
          "imageAssetId": null,
          "collapsed": false,
          "extensions": {}
        }
      },
      "relationships": []
    }
  ],
  "extensions": {}
}
```

规则：

- 节点 ID 与标题解耦并跨保存稳定。
- 同级顺序只由 `childIds` 决定。
- 服务端校验无环父子关系、每 Sheet 唯一根、节点可达、关系线目标有效、样式合法和容量限制。
- 只有定义了往返规则的未知字段才允许保存在命名空间化 `extensions` 中。
- `collapsed` 属于共享文档状态还是用户视图状态，需要在画布 PoC 后一次性确定，正式数据产生后不得随意变更语义。

## 4. Redis 设计

| Key | 内容 | TTL |
|---|---|---|
| `session:{sessionId}` | 用户、工作空间、有效角色 | 会话策略控制 |
| `sessions:user:{userId}` | 用户的有效会话 ID 集合 | 不短于其最长会话 |
| `ratelimit:login:account:{loginHash}` | 按标准化登录名计数 | 15 分钟 |
| `ratelimit:login:source:{sourceHash}` | 按安全处理后的来源计数 | 15 分钟 |
| `lock:document:{documentId}` | 会话、编辑会话、凭证摘要、代次、心跳 | 心跳后 15 分钟 |
| `presence:document:{documentId}` | 在线会话集合 | 随连接维护 |
| `import:user:{userId}:waiting` | 用户等待任务 | 随任务维护 |
| `import:workspace:{workspaceId}:waiting` | 工作空间等待任务 | 随任务维护 |
| `ratelimit:{scope}:{key}` | 窗口计数 | 按策略 |

锁与队列名额的获取、心跳、释放和强制释放使用 Lua 或等价原子操作。

## 5. MinIO 对象路径

对象键只使用内部 ID，不使用用户输入名称：

```text
org/{orgId}/workspace/{workspaceId}/original/{documentId}/{objectId}.xmind
org/{orgId}/workspace/{workspaceId}/snapshot/{documentId}/{version}/{objectId}.json
org/{orgId}/workspace/{workspaceId}/asset/{sha256-prefix}/{assetId}
org/{orgId}/workspace/{workspaceId}/temp/import/{jobId}/{objectId}
org/{orgId}/workspace/{workspaceId}/export/{jobId}/{objectId}.xmind
backup/{backupId}/...
```

临时和导出对象配置生命周期过期。下载必须先鉴权，再使用服务端流式响应或短期签名 URL。

## 6. REST API

统一前缀 `/api/v1`，OpenAPI 作为前端类型生成来源。

### 6.1 登录和当前用户

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/auth/login` | 校验本地账号密码并建立会话 |
| `POST` | `/auth/logout` | 撤销当前服务端会话 |
| `PUT` | `/auth/password` | 校验当前密码、修改密码并撤销全部会话 |
| `GET` | `/me` | 当前用户、角色和有效权限 |

登录接口无论账号不存在、密码错误或账号禁用，对外都返回 `AUTH_INVALID_CREDENTIALS` 和统一的安全提示。`must_change_password=true` 的会话只允许访问 `/me`、`/auth/password` 和 `/auth/logout`。修改成功后当前会话也失效，用户需使用新密码重新登录。

### 6.2 成员和审批

| 方法 | 路径 | 权限 |
|---|---|---|
| `POST` | `/workspaces/{id}/edit-requests` | Reader |
| `GET` | `/admin/edit-requests` | Admin |
| `POST` | `/admin/edit-requests/{id}/approve` | Admin |
| `POST` | `/admin/edit-requests/{id}/reject` | Admin |
| `POST` | `/admin/members/{id}/revoke-editing` | Admin |
| `GET` | `/admin/members` | Admin |

| `POST` | `/admin/members/{id}/password/reset` | Admin；生成一次性临时密码并撤销旧会话 |
| `PATCH` | `/admin/members/{id}/account-status` | Admin；禁用或恢复账号 |

审批接口需要幂等键，或通过终态约束实现幂等。创建账号和重置密码接口使用密码学安全伪随机数生成器，只在成功响应中显示一次临时密码，不写入审计元数据或应用日志。禁用账号前必须锁定相关成员行并确保操作后至少剩余一个有效 Admin。

## 7. Socket.IO 契约

命名空间：`/workspace`，连接时使用同一服务端会话鉴权。

客户端事件：

| 事件 | Payload |
|---|---|
| `document:join` | `{ documentId, knownVersion }` |
| `document:leave` | `{ documentId }` |
| `presence:ping` | `{ documentId }` |
| `import:subscribe` | `{ batchId }` |

编辑锁和保存继续使用 REST，以便明确处理幂等与错误；Socket.IO 仅广播已提交结果。

服务端事件：

| 事件 | 用途 |
|---|---|
| `document:snapshot` | 完整已提交快照和更高版本 |
| `document:reload-required` | 版本跳跃或状态异常，要求 REST 重载 |
| `document:trashed` | 文档已删除，通知跳转 |
| `lock:state` | 锁拥有者、心跳、代次和可用性 |
| `lock:forced-release` | 原编辑者切换只读 |
| `presence:state` | 实时房间在线状态 |
| `import:progress` | 单任务阶段和百分比 |
| `import:result` | 单任务最终结果和安全失败原因 |
| `notification:new` | 新平台通知元数据 |

每个事件信封包含 `eventId`、`occurredAt`、`requestId` 和适用的工作空间/文档版本。

## 8. 统一错误码

- 认证：`AUTH_REQUIRED`、`AUTH_SESSION_EXPIRED`、`AUTH_INVALID_CREDENTIALS`、`AUTH_PASSWORD_CHANGE_REQUIRED`、`AUTH_CURRENT_PASSWORD_INVALID`。
- 权限：`PERMISSION_DENIED`、`EDIT_PERMISSION_REQUIRED`。
- 名称：`NAME_REQUIRED`、`NAME_TOO_LONG`、`NAME_CONFLICT`。
- 容量：`FOLDER_LIMIT_REACHED`、`FOLDER_DOCUMENT_LIMIT_REACHED`、`WORKSPACE_DOCUMENT_LIMIT_REACHED`。
- 锁：`DOCUMENT_LOCKED`、`LOCK_NOT_OWNED`、`LOCK_EXPIRED`、`LOCK_FORCED_RELEASED`。
- 文档：`DOCUMENT_VERSION_CONFLICT`、`DOCUMENT_TRASHED`、`DOCUMENT_NODE_LIMIT_REACHED`。
- 导入：`FILE_TYPE_UNSUPPORTED`、`FILE_TOO_LARGE`、`FILE_DUPLICATE`、`FILE_DAMAGED`、`XMIND_INCOMPATIBLE`、`IMPORT_QUEUE_USER_LIMIT`、`IMPORT_QUEUE_WORKSPACE_LIMIT`、`IMPORT_TIMEOUT`、`IMPORT_CANCEL_NOT_ALLOWED`。
- 图片/配额：`IMAGE_TYPE_UNSUPPORTED`、`IMAGE_TOO_LARGE`、`DOCUMENT_IMAGE_LIMIT`、`STORAGE_QUOTA_EXCEEDED`。
- 恢复：`RESTORE_NAME_CONFLICT`、`HISTORY_VERSION_EXPIRED`。
- 系统：`RATE_LIMITED`、`DEPENDENCY_UNAVAILABLE`、`INTERNAL_ERROR`。

每个错误码只能映射到一种已记录的 HTTP 状态和默认安全提示。

## 9. 事务与幂等

- 重命名和移动在同一事务中校验名称/容量并写审计。
- 保存先写不可变对象，再以事务插入版本元数据、推进当前版本和写审计；事务失败产生的孤儿对象异步清理。
- 历史恢复锁定文档行，校验编辑锁和版本，保留恢复前版本，创建恢复版本并推进当前指针。
- 文件夹删除/恢复在关系数据层原子处理其中全部文档；对象仅在永久删除时异步清理。
- 导入创建和完成以任务 ID 幂等。
- 可能因用户重试产生重复数据的 POST 请求使用 `Idempotency-Key`。
- 通知和邮件采用 Outbox 表加 Worker，避免业务事务提交后通知丢失。
- 账号创建在同一事务中写入用户、本地身份、Reader 成员关系和审计记录。
- 密码修改/重置和账号禁用成功后必须撤销用户会话；会话撤销失败时操作不得静默返回成功，并必须产生系统告警。

## 10. 定时保留任务

- 清理 90 天前通知。
- 回收站到期前三天通知管理员。
- 永久清理到期回收站对象并释放空间。
- 清理超过 7 天或超出 30 个的历史版本。
- 清理放弃的导入任务和临时文件。
- 对账 PostgreSQL 引用与 MinIO 对象；发现异常孤儿先报告，不直接删除。

所有清理任务使用有界批次、保证幂等，并为实质性删除写入审计。
