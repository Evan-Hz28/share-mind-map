# 共享思维导图平台分阶段开发计划

版本：V1.1  
状态：首版交付计划  
更新日期：2026-09-16

## 1. 计划假设

以下周期按 3～5 名工程师，加上兼职产品、设计和测试支持估算。如果实际人员更少，或公司内网基础设施尚未准备，周期需要顺延。

首版预估：需求和设计确认、环境可用后约 12～16 周。

外部前置条件：

- 公司内网服务器、域名/TLS、SMTP 通道和部署权限。
- 接近生产配置的 PostgreSQL、Redis、MinIO 资源。
- 开发、产品、测试团队提供真实代表性 XMind 样本，包括大文件和含图文件。
- 明确系统维护者、首个管理员及初始登录名，并准备安全交付一次性临时密码的渠道。

## 2. 交付原则

- 画布与解析器 PoC 通过后再锁定编辑器排期。
- 每个阶段交付可演示、可测试、可迁移的纵向能力。
- 固定 P0 范围，多人同时编辑、多级文件夹和测试执行不进入首版。
- 权限、审计、版本检查和数据保护必须随功能一起完成，不留到最后补。
- 对删除、恢复、锁和并发等高风险流程建立确定性的自动化测试。

## 3. 阶段 0：方案落地与技术验证（1～2 周）

工作内容：

- 确认登录、全部文档、导入、查看/编辑、回收站、通知和后台的交互稿。
- 定稿标准文档 Schema V1 和 OpenAPI 规范。
- 按统一指标验证 `simple-mind-map`、MindElixir 和其他可行组件。
- 建立 XMind 样本库：当前/旧版格式、多 Sheet、图片、样式、关系线、备注、标签、未知扩展、损坏文件、恶意 ZIP、5,000 和 20,000 节点。
- 实测渲染、选中、拖动、完整快照替换和内存。
- 验证 Node Worker 安全解析和 ZIP 防护。
- 建立本地 Docker Compose 骨架。

退出标准：

- 画布组件通过许可证和性能门槛，或明确收缩编辑范围。
- 标准模型可以往返转换全部承诺特性。
- 导入风险与不兼容特性有样本和结论。
- Web、API、Worker、PostgreSQL、Redis、MinIO 可一键启动。

## 4. 阶段 1：平台基础（2 周）

后端：

- NestJS 模块骨架、配置校验、迁移、OpenAPI、请求 ID、统一错误和结构化日志。
- Argon2id 本地凭证、服务端会话、退出、登录限流、首次强制修改密码和账号禁用。
- 组织、工作空间、用户、认证身份、成员关系、幂等的首个管理员初始化命令和受控的管理员账号恢复命令。
- 管理员创建账号、重置临时密码、禁用/恢复账号和撤销用户全部会话。
- Reader、Editor、Admin 服务端守卫。

前端：

- Vue 3/Vite、Element Plus、Pinia、Vue Router、生成式 API Client、响应式应用框架。
- 账号密码登录、首次修改密码、失败状态和权限感知导航。

工程：

- Docker Compose 开发环境。
- `.env.example`、密钥注入、健康检查、数据库迁移命令。
- Lint、类型检查、单元/集成测试和构建流水线。

退出标准：

- 预创建用户能够登录并作为 Reader 访问工作空间，未预创建用户无法自行注册。
- 临时密码首次登录后必须修改，登录限流、密码重置、账号禁用、最后管理员保护和全会话撤销通过集成测试。
- 隐藏前端控件之外，后端也能拒绝所有越权请求。

## 5. 阶段 2：工作台与权限（2 周）

- 成员列表以及管理员创建账号、一次性重置密码、禁用/恢复账号界面。
- 一级文件夹 CRUD 和数量限制。
- 文档列表、排序、分页/虚拟列表、重命名、移动和限制。
- 编辑申请、管理员通过/拒绝和即时撤销。
- 权限相关平台通知。
- 审计基础服务和管理员查询。
- 存储使用量和配额阈值。

退出标准：

- Reader/Editor/Admin 权限矩阵通过集成测试。
- 命名、重名、文件夹/文档数量和配额边界均由事务保证。
- 撤销权限立即生效且不会静默丢失未保存内容。

## 6. 阶段 3：XMind 导入与导出（2～3 周）

- 多文件预检、默认当前文件夹和单文件目标调整。
- MinIO 流式临时上传、文件校验和 SHA-256。
- Redis 队列：并发 3、用户等待 10、工作空间等待 50、任务 5 分钟超时。
- 安全解压、解析、标准化、节点限制、兼容性报告和原文件保留。
- Socket.IO 进度、逐文件结果、等待任务取消、重试/替换/改名/改目录。
- 导出前保存、当前文档名和尽力保持原特性。
- 管理员导入失败视图。

退出标准：

- 一个坏文件不会影响同批其他文件。
- 关闭/取消时保留成功结果，按规则取消未完成任务并清理临时数据。
- 名称/内容查重和配额预检通过并发竞争测试。
- 全部样本得到明确兼容性结果并可导出合法 `.xmind`。

## 7. 阶段 4：查看、编辑、锁与图片（3～4 周）

编辑器：

- 左侧目录与画布适配层。
- 桌面只读/编辑和移动端只读布局。
- 新增、删除、改名、改层级、排序、优先级、备注、标签、图标、基础样式、折叠和撤销。
- 文件选择、粘贴、拖拽图片及 PNG/JPEG/WebP、大小和配额校验。

协作：

- 开始/结束编辑、浏览器会话锁、心跳、15 分钟过期。
- 管理员强制释放。
- 自动/手动保存、脏状态、基准版本校验和完整快照。
- Socket.IO 房间、在线成员、当前编辑者和最近保存时间。
- 快照广播、高版本过滤、版本跳跃重载、重连和视图状态恢复。
- 断网切只读以及未保存内容临时保留/复制/导出草稿。

退出标准：

- 同一文档只有一个浏览器会话可以保存。
- 过期或强制释放会话的延迟保存会被拒绝。
- 所有测试路径都不会静默丢弃未保存内容。
- 100 人实时房间及超额普通只读符合约定。
- 5,000/20,000 节点达到性能目标。

## 8. 阶段 5：历史、搜索、回收站与后台（2～3 周）

- 自动版本 5 分钟合并、手动即时版本、7 天/30 个保留。
- 历史查看、锁内恢复、恢复前版本保留和恢复后广播。
- 文件夹/文档/节点搜索及优先级、标签、创建人、更新时间筛选。
- 路径展示、定位高亮、上一个/下一个匹配。
- 文档/文件夹回收站、非空文件夹整体删除、冲突阻止恢复、到期提醒和自动清理。
- 管理员永久删除和清空回收站。
- 会话、锁、存储、导入失败和基础系统状态页面。

退出标准：

- 历史恢复生成新版本并保留恢复前内容。
- 搜索不返回越权内容，旧索引任务不能覆盖新版本。
- 回收站可恢复结构/排序并阻止全部已定义冲突。
- 永久删除仅在全部持久引用解除后释放存储。

## 9. 阶段 6：加固、恢复和上线（2 周）

- Chrome/Edge 最新两个大版本验证，移动端只读验证。
- 登录、导入、图片上传和 Socket.IO 限流。
- CSRF、CORS、CSP、安全 Cookie、对象下载鉴权、压缩包安全和日志脱敏检查。
- 按约定 P95 和大文档目标压测。
- 每日备份、完整性校验、恢复脚本和隔离环境完整演练。
- 服务依赖、导入持续失败、队列积压、存储阈值的平台/邮件告警。
- 固定发布脚本：检查、备份、兼容迁移、镜像更新、健康验证。
- 管理员手册、用户说明和运维 Runbook。
- 使用选定真实项目文档进行 Pilot 导入。

退出标准：

- P0 端到端测试、安全清单、备份恢复和性能门槛全部通过。
- 演示在 4 小时内完成恢复，否则需要签署明确例外。
- Pilot 用户接受 XMind 保真度及已知限制。
- 在已迁移的兼容数据库上完成应用镜像回滚演练。

## 10. P0 功能清单

- 管理员预创建本地账号、首次强制改密码、登录限流、服务端会话、退出、密码重置和账号禁用。
- 默认只读、编辑申请、审批/拒绝/撤销。
- 全部文档、一级文件夹、列表、排序、搜索和导航。
- 多文件 XMind 导入、限制、兼容报告、原文件、失败处理和重试。
- XMind 式只读画布和已承诺的节点编辑能力。
- 单编辑者锁、心跳、过期、强制释放和版本安全保存。
- 自动/手动保存和未保存内容保护。
- 限制内 PNG/JPEG/WebP 图片。
- 保存后完整快照推送和重连恢复。
- 历史版本和恢复。
- 回收站、恢复冲突、管理员永久删除和到期清理。
- 所有 Reader 可导出 `.xmind`。
- 平台通知和严重故障邮件。
- 审计、存储、导入失败、会话/锁和系统状态管理。
- 备份、健康检查、结构化日志、关键告警和发布回滚流程。

## 11. 后续版本清单

- CRDT/OT 多人同时编辑。
- Lark OAuth 与 Lark 组织同步。
- 多组织和多工作空间。
- 文件夹/文档权限和外部分享。
- 多级文件夹和批量操作。
- 测试执行状态、轮次、报告和指标。
- 对外 API。
- 完整移动端、深色模式、Firefox/Safari 承诺。
- 通用附件、GIF/SVG 和高级 XMind 私有布局。
- Kubernetes、高可用、ELK/OpenSearch、Prometheus/Grafana。

## 12. 测试策略

### 12.1 单元测试

- 名称标准化和长度。
- 登录名标准化、密码边界和临时密码状态。
- 角色与权限计算。
- 标准文档树结构不变量。
- XMind 映射与兼容性分类。
- 版本合并与保留。
- 配额计算。
- 错误映射和敏感信息脱敏。

### 12.2 API 集成测试

- PostgreSQL 事务和唯一约束竞争。
- PostgreSQL 用户/身份/成员创建事务和登录名唯一约束。
- Redis 会话、全会话撤销、登录限流、锁原子性/过期和队列名额。
- MinIO 生命周期和对象鉴权。
- 保存版本冲突和失效锁凭证。
- 文件夹整体删除和恢复事务。
- 导入幂等、取消、超时和清理。

### 12.3 端到端测试

- 首个管理员初始化，管理员创建 Reader，Reader 使用临时密码登录并强制改密码。
- 错误密码限流、管理员重置密码、禁用账号、最后管理员保护、维护者账号恢复和全会话撤销。
- Reader 申请编辑，管理员审批和撤销。
- 单个/多个 XMind 混合结果导入与失败重试。
- 两个浏览器会话争用编辑锁，管理员强制释放。
- 编辑、自动保存、手动保存、只读更新、重连和导出。
- 断网且存在未保存内容。
- 删除子树、撤销和历史恢复。
- 删除非空文件夹、恢复、冲突阻止和永久删除。
- 搜索结果打开、展开、定位和切换匹配项。

### 12.4 非功能测试

- 5,000 和 20,000 节点大文档。
- 用户/工作空间队列上限和 3 Worker 并发。
- 100 人实时房间及超额只读。
- 恶意/损坏 XMind 和伪造图片。
- 每个接口和事件的权限矩阵。
- 备份完整性与完整恢复。

## 13. 完成定义

功能只有同时满足以下条件才算完成：

- 正常、空、加载、失败和无权限状态完整。
- REST/OpenAPI 或 Socket.IO 契约已记录，生成类型保持最新。
- 服务端鉴权和审计已实现。
- 核心规则有单元/集成测试，高风险流程有端到端测试。
- 日志结构化且不含敏感内容。
- 数据库迁移与上一版应用兼容。
- 完成适用的可访问性、浏览器和响应式验证。
- 故障与恢复方式写入运维说明。

## 14. 上线检查

- 首个管理员一次性初始化命令和受控账号恢复命令验证通过，不存在默认账号或代码内置密码。
- 组织、工作空间、配额、保留时间和首个管理员已配置。
- Argon2id 参数、密码策略、登录限流、密码重置和全会话撤销通过检查。
- TLS、Cookie、CORS、CSP、SMTP、PostgreSQL、Redis、MinIO 配置通过检查。
- 密钥不在 Git 且服务器文件权限正确。
- 发布前备份完成且完整性校验通过。
- 数据库迁移预演和应用回滚演练完成。
- P0 自动化与浏览器冒烟通过。
- 代表性 XMind 兼容报告经业务确认。
- 类生产环境性能达标。
- 告警接收人和配额阈值已测试。
- 明确每月恢复演练负责人和日程。
- 已向 Pilot 用户发布已知限制和支持流程。

## 15. 立即执行事项

1. 指定产品、技术、测试和系统维护负责人。
2. 评审并将本组四份基线文档纳入版本控制。
3. 确定首个管理员的登录名，并准备参考部署环境。
4. 从开发、产品、测试团队收集代表性 XMind 样本。
5. 执行阶段 0 的画布/解析器 PoC 并发布实测结论。
6. 冻结标准文档 Schema V1 和第一版 OpenAPI 骨架。
7. 按实际人员和 PoC 结果重新估算阶段 1～6。
